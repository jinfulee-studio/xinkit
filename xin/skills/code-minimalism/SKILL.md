# 代码最小性三位一体（同功能·最少代码）

> 委派**代码类** agent（impl / bugfix / test / 重构 / architect）与自己动手写代码时的**默认律**。
> 一句话：**同样的功能，用最少的代码实现。**

## 公理：三个面向，一条统一律

### ① 最少代码 = 最小本质复杂度（**不是**代码高尔夫）
- 每一行都要挣得它的位置。删投机抽象、删死代码、删重复。
- 加代码前先问：**能不加吗？能复用既有/库吗？能砍掉这个需求吗？**
- 本质复杂度（问题固有）保留；偶然复杂度（实现引入）清零。
- 🔴 红线：**牺牲可读性换字符数 = 违规**。「最少」≠「最短」，是**最少的「需要被理解的东西」**。
- 锚：Kent Beck《4 Rules of Simple Design》**是有序的**——passes tests ＞ reveals intention ＞ no duplication ＞ **fewest elements**（最低优先，仅前三满足后才考虑；与「揭示意图」冲突时让步）＋ YAGNI。

### ② 量子模块化 = 单一职责、**深而非浅**的最小独立单元
- **单一职责定边界**：一个模块/函数只做一件事（SRP）。
- **深而非浅定大小**：窄接口 + 富实现（复杂度藏在内部）。🔴 量子 ≠ 越拆越碎——过度拆小制造 shallow modules（接口/实现比过高）= classitis，反而抬高跨模块认知。**职责单一才拆，拆完每块更清晰才算对**。
- 高内聚 / 低耦合 / 可组合；单模块可独立开发、测试、替换、读懂。
- 🔴 YAGNI：禁为「将来可能用的未知需求」预建抽象。**调用点数是信号非红线**——错误处理类型 / 测试隔离接口 / DDD 边界 Adapter 第一次引入时只有 1 处调用是**正当的**（有架构隔离理由 = 例外）。
- 锚：SRP（Robert C. Martin）＋ Bounded Context（Eric Evans DDD）＋ Unix「do one thing well」；**深模块边界** = Ousterhout《A Philosophy of Software Design》（窄接口·深实现·反 classitis，正是防「拆过头」的护栏）。

### ③ AI 易维护 = 最低认知负荷
- 清晰命名（**名字即文档**）、可预测结构、自解释；注释只解释「为什么」。
- 数据流单向可追、依赖显式不隐藏、状态最少。
- 锚：Hickey《Simple Made Easy》— simple = **不缠绕**（无共享可变状态 / 无隐式依赖 / 副作用显式 / 不靠继承与条件分支缠绕）；decomplecting 是根本目标，**模块大小是结果不是手段**。

## 统一律
**最小化「总维护表面积」**（≈ 接口数 × 跨模块暴露面 × 认知负荷，**不是字符数/行数**）＝ 少=多 应用于代码 ＝ 降熵 ＝ 净复利智能。
🔴 **冲突优先级**：当「可读性 / 独立可测试性」与「行数最少」冲突时，**前者优先**。拆分多出几行接口/导出是可接受代价——只要每块职责更清晰；若拆完职责没更清晰则不拆。「三位一体不冲突」的前提是用「维护表面积」度量而非「字符数」。

## 代码 agent 自检清单
**写之前**：① 能用既有代码/库实现吗？② 需求能砍吗，最小可用是什么？
**写之中**：③ 新抽象有当下真实需求吗（纯为「将来」且无架构理由 → YAGNI 删）？④ 每模块单一职责、深实现窄接口、可独立测试吗？⑤ 命名自解释到不需注释吗？
**写之后**：⑥ 能删掉任何一行而功能/可读不变吗——能就删。⑦ 拆分判据是「单一职责更清晰」而非「低于行数阈值」。⑧ 可读性有没有为了短被牺牲（违规则回退）？

## 反模式（canonical 检测清单 — 审查 / 扫描 / 自检共用）
- **投机抽象**：为「将来未知需求」建的接口/基类/泛型/配置，当下 0–1 实现**且无架构隔离理由**（测试/边界/依赖倒置例外）。
- **死代码**：未被调用的导出、注释掉的代码块、unreachable 分支。
- **过度分层**：一个调用穿过 ≥4 层**纯转发**包装（函数体仅一行 return 上层调用，无转换/验证/映射逻辑）。Clean Architecture / Hexagonal 等职责明确的分层**不适用**此条。
- **重复 / 反向重复**：≥3 处近似代码块未抽取（违 DRY）；或抽取了只用 1 次的伪复用。
- **超大单元**：单文件 >450 行 / 单函数 >60 行（经验阈值 E，按语言/项目校准）= 量子拆分**信号**。🔴 拆分理由是单一职责，不是「降到阈值以下」——禁拆成 449 行的数字高尔夫。
- **代码高尔夫**：为短牺牲可读（嵌套三元/魔法单行/隐晦缩写）。

## 审查维度 rubric（review agent 第 5 维，与 安全/性能/可维护/规范 并列）
逐条核对上方「反模式」6 项 ＋ 问：同功能有无更少代码的实现？
输出：每条 PASS / 标记问题 ＋ **行号** ＋ **最小化改写建议**。
