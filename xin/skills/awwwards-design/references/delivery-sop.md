## 1. 角色

小团队可由一人兼任，但审批视角不得省略。

| 角色 | 主要责任 | 不得单独批准 |
|---|---|---|
| Product/Business Owner | 业务结果、范围、风险与上线决定 | 视觉质量、无障碍技术符合性 |
| Creative Lead | 概念、品牌、视觉与动效一致性 | 自己作品的最终发布 |
| UX/Content Lead | 用户任务、信息架构、研究与内容准确 | 性能与代码质量 |
| Accessibility Reviewer | WCAG、键盘、辅助技术与减少动效 | 品牌方向 |
| Frontend/Performance Lead | 实现、响应式、回退、WPO 与浏览器质量 | 业务风险接受 |
| Release Approver | 汇总证据并作 GO/HOLD/NO-GO | 在证据未知时批准 |

若多 Agent 可用，创意、UX/无障碍、工程三个评审必须独立看原始产物，再汇总；不要先给它们预期结论。

## 2. 阶段与门禁

### 强制状态机

每个门禁只能处于：

- `DRAFT`：产物未齐；
- `PENDING`：产物已提交，等待真实审批；
- `APPROVED`：批准证据完整；
- `REJECTED`：已明确退回；
- `SKIPPED`：因范围或权限未执行。

只有 `APPROVED` 可以正式进入下一门禁。`PENDING` 或 `SKIPPED` 时可继续做 `PROVISIONAL` 探索草案，但不得称为已过门禁，发布决定恒为 `HOLD`。任一门禁状态变化都记录产物版本、真实批准者、批准原文、时间和适用范围；“尽快做”“直接继续”或作者自评不算批准。

| 门禁 | 必需产物 | 通过标准 | 退回条件 | 批准角色 |
|---|---|---|---|---|
| D-G0 问题定义 | 设计简报、用户任务、成功指标、证据缺口 | 主要受众、任务、业务结果与约束清楚 | 方向会因未知受众/目标而改变 | Product + UX |
| D-G1 参考与概念 | 参考矩阵、拒绝复制项、三个概念领地 | 概念原创、与品牌/用户有证据连接、风险透明 | 只是换皮；依赖未经许可资产 | Creative + Product |
| D-G2 IA 与内容 | 页面地图、故事脊柱、线框、内容清单 | 无动效也能理解并完成关键任务 | 价值主张、证据、CTA 或阅读顺序失败 | UX + Content |
| D-G3 系统与原型 | tokens、关键组件状态、动效原型、回退方案 | 桌面/移动/键盘/减少动效行为均被定义 | 只有理想桌面状态；无失败/回退 | Creative + A11y + Frontend |
| D-G4 实现候选 | 可运行构建、测试数据、资产许可、分析计划 | 关键路径完整，质量预算可测 | 核心功能依赖装饰技术或未知第三方 | Frontend + UX |
| D-G5 独立审计 | 四维预评、Q-G01–Q-G12 发布门禁、缺陷清单、至少一轮同环境前后复测与回归证据 | 无 P0；关键证据齐全；分数有依据 | 零轮复测；用高总分掩盖阻断项；自评无独立复核 | Independent reviewers |
| D-G6 发布 | 决策记录、负责人、监测和回滚方案 | GO 或有已核验风险接受的 CONDITIONAL-GO | 关键证据未知；无回滚或责任人 | Release Approver |

没有完整批准记录时，用 `PROPOSED`、`ASSUMED` 或 `PENDING`；不得写 `APPROVED`。

### 不可降级阻断项

以下确认问题不可用审美分、期限或普通风险接受抵消：

- 关键任务在主要移动端、键盘或触摸路径中无法完成；
- 键盘陷阱、危险闪烁，或核心内容/控件没有可访问替代；
- 关键导航、表单、购买、联系或 CTA 损坏且无可靠回退；
- 未经授权资产、虚构客户/指标/奖项或会误导用户的关键声明；
- 用户数据、安全、法务或付款路径存在确认的高影响风险；
- 产物声称 WCAG 或 Core Web Vitals 通过，却没有相应有效证据。

遇到这些问题时为 `NO-GO`。其他未测的发布关键项为 `HOLD`，不能默认通过或默认记零分。

## 3. 自我迭代

### 证据循环

1. **Baseline**：保存版本、视口、设备/网络、分数、任务结果和已知限制。
2. **Diagnose**：把问题映射到用户、业务、四维评分和发布门禁。
3. **Root cause**：优先找同时造成多个症状的系统性原因。
4. **Batch**：一次只改变一个概念假设或一组共同根因。
5. **Verify**：用相同环境复测，另做关键路径回归。
6. **Compare**：报告绝对值、差值、置信度和副作用。
7. **Decide**：保留、回退或进入下一轮。

D-G5 前至少完成一轮完整循环。零轮必须 `HOLD`。若因成本或范围停止，记录真实决策者、原文、时间、版本与残余风险；Agent 自己判断“不值得”不能关闭问题。

### 优先级

顺序默认如下：

1. 法律、安全、可访问性与关键任务阻断；
2. 内容真实性、信息架构与用户理解；
3. 性能、稳定性与响应式；
4. 视觉系统一致性；
5. 创意差异化与愉悦细节。

一个高杠杆修改优先于多个表面修补。例如：重写首屏叙事可能同时改善 Content、Usability、Design 层级与转化，不应先微调十个动画时长。

### 停止规则

在以下任一条件满足时停止当前循环并请求决策：

- 已通过批准门槛且残余问题不改变决定；
- 下一步需要新的品牌资产、内容、预算、权限或业务取舍；
- 连续两轮指标无实质提升，需要改变根因假设；
- 改善一个维度会显著伤害更高优先级门禁；
- 继续工作超出已批准范围。

## 5. 验收清单

### 概念与原创性

- 概念可由品牌事实和用户张力解释；
- 签名机制与内容含义绑定；
- 参考有 URL/日期，复制禁区清楚；
- 移除品牌名后不会与任意 AI/SaaS 模板互换。

### 内容与任务

- 5 秒内可理解“是什么、给谁、带来什么”；
- 关键任务无装饰技术也能完成；
- 证据、数据、客户和奖项可追溯；
- CTA、导航和错误恢复明确。

### 系统

- 排版、网格、色彩、媒体、动效和状态使用语义规则；
- 桌面、移动、触摸、键盘、减少动效和失败回退已定义；
- 异常组件不是无规则例外；
- 资产许可与字体语言覆盖明确。

### 发布

- WCAG 2.2 AA 关键项有人工与自动证据；
- 移动/桌面 CWV 使用真实用户数据；若尚无数据，明确标为待观测并保留实验室结果；
- 浏览器、低性能、无 JS/媒体失败和 200% 文本缩放已测试；
- 没有 P0，P1 有负责人、期限与风险接受；
- 发布监测、回滚与最终批准者明确。
