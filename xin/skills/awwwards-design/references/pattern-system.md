# Awwwards 级体验模式系统

## 1. 不变量与变量

### 高质量不变量

1. **明确的创意命题**：用户能感知“为什么是这种体验”。
2. **内容与品牌驱动**：构图、媒体、字体和互动来自真实内容，不是套模板。
3. **强而有序的层级**：首屏、章节、证据与行动路径形成可扫描叙事。
4. **受控张力**：不对称、重叠、尺度冲突或留白有稳定对齐系统托底。
5. **一致的动效语法**：少量时长、缓动和编排规则贯穿状态与章节。
6. **一个签名式机制**：最值得记忆的互动与产品/故事含义绑定。
7. **细节完整**：加载、焦点、触摸、错误、空状态、移动端和回退都被设计。
8. **创造力不排除用户**：实验层可降级，核心内容与任务不依赖炫技。

### 项目变量

浅色或深色、极简或繁复、二维或三维、编辑式或应用式、静态或高动效、常规或非线性导航都属于变量。任何变量都必须有品牌、内容或任务依据。

## 2. 表达包络

| 情境 | 默认表达强度 | 签名机制放置 | 主要风险 |
|---|---|---|---|
| 高频 SaaS / 工具 | 低到中 | 演示、数据反馈、局部状态转场 | 可读性、速度、认知负担 |
| B2B 营销 / 品牌站 | 中 | Hero、案例叙事、产品机制 | 价值主张被视觉吞没 |
| 电商 / 转化路径 | 中，探索层可高 | 商品发现、试用、对比 | 导航、搜索、结账受阻 |
| 作品集 / 创意机构 | 中到高 | 作品索引、项目过渡、媒体编排 | 同质化、加载与移动端 |
| 文化 / 娱乐 / 发布活动 | 高但可退出 | 世界观、章节或空间叙事 | 眩晕、控制丢失、内容不可达 |
| 公共服务 / 高风险交易 | 低 | 信息解释、进度与确认 | 错误、排除、法律风险 |

高风险或高频任务不等于平庸；把原创性放在内容表达、信息模型、品牌语言和反馈细节中。

## 3. 六种体验原型

### A. 编辑式叙事 Editorial Narrative

- 适合：文化、出版、品牌历史、复杂观点。
- 核心：章节节奏、排版尺度、媒体注释、滚动中的内容揭示。
- 签名机制：目录/脚注/时间轴/文本与媒体的语义联动。
- 禁忌：为了版式牺牲阅读顺序和行长。

### B. 沉浸式世界 Immersive World

- 适合：娱乐、游戏、活动、具有强资产的品牌发布。
- 核心：空间隐喻、声音、场景、探索。
- 签名机制：有意义的 3D/WebGL/Canvas 交互。
- 禁忌：强制预加载、无出口、核心信息只存在于 Canvas。

### C. 产品剧场 Product Theatre

- 适合：硬件、工业、AI、技术产品。
- 核心：产品结构、机制演示、前后对比、证据。
- 签名机制：360、剖面、参数或真实 UI 与叙事联动。
- 禁忌：产品不可理解，只剩抽象粒子。

### D. 商务发现 Commerce Discovery

- 适合：时尚、奢侈品、生活方式、电商。
- 核心：发现、筛选、试用、商品故事与购买连续性。
- 签名机制：视觉搜索、搭配、沉浸式浏览的可选层。
- 禁忌：异常导航破坏搜索、库存、价格、购物车和结账。

### E. 身份化作品集 Identity Portfolio

- 适合：工作室、创作者、建筑、摄影。
- 核心：观点、选择、案例、角色和结果。
- 签名机制：作品索引、项目切换或媒体编排体现创作者方法。
- 禁忌：只展示封面，不说明贡献、过程与影响。

### F. 清晰型创意系统 Clear Creative Utility

- 适合：SaaS、服务平台、数据产品、公共信息。
- 核心：任务清晰、模块化内容、真实产品证据。
- 签名机制：数据、工作流或状态反馈形成品牌记忆。
- 禁忌：把营销炫技带进高频操作路径。

## 4. 原创概念公式

用以下四项形成概念，不从特效名称开始：

`概念 = 品牌真相 × 用户张力 × 独有内容资产 × 可交互隐喻`

示例结构：

- 品牌真相：产品把分散流程连接起来；
- 用户张力：用户在多个工具间失去上下文；
- 内容资产：真实工作流与审计轨迹；
- 交互隐喻：一条可追踪的路径把零散节点变成决策；
- 签名机制：滚动/操作时路径连接真实产品证据，而不是装饰粒子。

概念必须能在纯文本、静态图与增强体验中保持同一含义，否则它只是效果。

## 5. 设计系统规格

### 内容

- 定义首屏承诺、用户问题、机制、证据、反对理由、行动；
- 每个章节只有一个主要叙事任务；
- 所有数据、客户、奖项与案例保留来源；
- 使用真实产品界面时，注明演示数据和状态。

### 排版

- 先定义角色：Display、Heading、Body、Label、Data、Caption；
- 为每个角色定义字族、字重、尺度范围、行高、字距、最大行长和语言回退；
- 大字号承担观点，小字号承担元数据；不要用极小字制造“高级感”；
- 字体加载失败时层级仍成立。

### 网格与空间

- 定义容器、列、gutter、baseline、间距级别和主要断点；
- 允许跨列、重叠和偏移，但每个例外都回扣一个锚点；
- 断点由内容破裂点产生，不由设备品牌产生；
- 移动端重排叙事，不把桌面缩小。

### 色彩与媒体

- 定义 Background、Surface、Text、Muted、Accent、Interactive、Focus、Success、Warning、Error 等语义角色；
- 在真实图片、视频和渐变背景上测量最差帧的可读性；
- 媒体要有职责：解释、证明、定调或导航；没有职责就删除；
- 视频提供海报、字幕/文字替代、控制和加载策略。

### 动效

每个动效只允许承担以下一种或多种职责：

- **Orientation**：说明用户在哪里、从哪来、到哪去；
- **Causality**：表现操作与结果的关系；
- **Hierarchy**：引导注意力顺序；
- **Narrative**：推进内容章节；
- **Delight**：在不阻碍任务时增加情绪。

为每个职责定义时长范围、缓动家族、距离/缩放上限、触发条件、取消方式和减少动效替代。避免同一视口多个主导动效争夺注意。

### 交互与状态

- 使用语义化原生控件作为基线；
- hover 必须有 focus 与 touch 等价状态；
- 自定义光标不能替代系统光标或唯一状态提示；
- 拖动、手势和横向滚动提供单指/按钮/键盘替代；
- 模态、菜单和转场定义焦点进入、循环、退出与恢复；
- 加载不遮蔽可先呈现的内容。

### 响应式与回退

至少定义：

- 320/360px 内容完整性；
- 触摸与粗指针行为；
- 键盘和屏幕阅读器顺序；
- `prefers-reduced-motion`；
- 节省数据、低性能或 WebGL 初始化失败；
- 无 JavaScript 与媒体失败；
- 横竖屏和文本放大 200%。

### 工程预算

先测基线，再按项目确定脚本、字体、图片、视频、3D、主线程和第三方预算。Core Web Vitals 使用一手门槛；包体数字属于项目决策，必须标明依据和测量环境，不能冒充 Awwwards 官方要求。

团队惯用默认值只适合形成 `PROVISIONAL` 假设，不构成证据。每个临时颜色、时长、断点或预算必须写出来源类别、验证方法和替换条件，且不能用于通过审批门禁。

## 6. 反模式检查

| 反模式 | 替代 |
|---|---|
| “深色 + 巨型无衬线 + 球体 = Awwwards” | 从品牌真相与内容资产生成概念 |
| 同时加入 WebGL、视频、视差、磁吸、横滚、转场 | 选择一个签名机制，其余服务层级 |
| 滚动劫持制造电影感 | 原生滚动 + sticky/章节编排 + 可取消动效 |
| 只做 Hero，后续回到模板卡片 | 让概念贯穿内容、状态与页尾 |
| 桌面是作品，移动端是删减版 | 为移动情境重新编排同等内容与任务 |
| 视觉分高就可发布 | 作品评分与发布门禁独立 |
| 用精确 token 掩盖没有品牌依据 | 先声明依据，再决定数值 |
