# 设计 Awwwards 级网站

## 核心契约

把“Awwwards 风格”解释为质量目标，不解释为一套固定皮肤。Awwwards 是评奖与作品社区，不是拥有单一视觉语言的设计公司。

始终追求：

`品牌真相 × 用户任务 × 内容叙事 × 原创概念 × 精确执行`

不要默认深色、巨型字体、WebGL、3D、自定义光标或滚动劫持。只有在它们强化概念、内容或任务时才采用。不得复制入选作品的独特构图、文案、插画、3D、动效序列或品牌识别。

Awwwards 官方主评分是 Design 40%、Usability 30%、Creativity 20%、Content 10%。将它用于方向校准，不把预测分数描述为官方评分或获奖保证。发布质量另设独立门禁，不能用高视觉分抵消可访问性、关键任务或性能失败。

## 开始前读取

- 需要事实、奖项门槛、来源或当前获奖样本时，读取 [references/evidence-base.md](references/evidence-base.md)。
- 需要选择风格方向、定义设计系统或动效语言时，读取 [references/pattern-system.md](references/pattern-system.md)。
- 需要项目排期、职责、审批、自我迭代或交付格式时，读取 [references/delivery-sop.md](references/delivery-sop.md)。

若任务要求“最新”“当前趋势”或直接引用某个 Awwwards 项目，重新访问官方页面核验；记录 URL 与访问日期。把结论标注为“官方事实”“样本归纳”或“项目决策”。

## 工作流

将 D-G0–D-G6 视为强制设计状态机。`D-` 命名空间用于区别审计 Skill 的 `Q-Gxx` 质量门禁。前一门禁没有完整证据与可验证批准时，不得把下一阶段标为“正式进行”或把产物标为可发布。为了继续探索，可以创建 `PROVISIONAL` 下游草案；必须把未过门禁标为 `PENDING` 或 `SKIPPED`，最终发布状态恒为 `HOLD`。期限、管理层口头催促或“直接做”不构成门禁批准。

### 1. 建立证据化设计简报

先提取或合理假设以下字段：

| 字段 | 必须回答的问题 |
|---|---|
| 业务结果 | 页面要让谁采取什么行动，成功如何衡量？ |
| 用户任务 | 用户为何而来，最短关键路径是什么？ |
| 品牌真相 | 哪些事实、语气、历史、产品机制或资产不可替代？ |
| 内容资产 | 有哪些真实文案、案例、数据、影像、产品界面或声音？ |
| 使用情境 | 设备、网络、访问频率、风险、辅助技术与语言是什么？ |
| 约束 | 技术栈、预算、期限、CMS、浏览器、法务和性能约束是什么？ |
| 证据缺口 | 哪些内容尚未验证，哪些只是推断？ |

信息不足但不影响方向时继续，并列出假设。若缺少的信息会改变受众、主任务、品牌方向或合规边界，只问一个最关键的问题。

### 2. 选择表达强度，不预选答案

依据访问频率、任务风险、内容密度和品牌许可，选择表达包络：

- 高频或高风险任务：清晰度优先，创意集中在品牌框架、内容和微交互。
- 低频探索或文化体验：允许更强叙事、空间感和沉浸技术，但保留控制与回退。
- 混合体验：入口与交易路径保持直接，把实验性交互放在可选探索层。

查看 `pattern-system.md` 中的多个体验原型，但此时不要锁定一个。后续三个概念至少横跨两个原型；不得直接把行业刻板印象当作品牌方向。

### 3. 建立参考矩阵

选择 6–12 个可追溯参考，至少包含：

- 3 个同类业务或相同用户任务；
- 2 个不同视觉原型，防止过拟合；
- 1 个移动端、无障碍或性能表现可验证的参考。

逐个拆解概念、信息架构、排版、构图、内容、动效、交互、响应式与技术回退。记录“借鉴原则”和“拒绝复制项”。不要只收集截图或形容词。

### 4. 生成三个原创概念领地

每个方向必须包含：

1. 一句概念命题；
2. 品牌证据与用户价值；
3. 页面故事脊柱；
4. 一个签名式交互，不是效果清单；
5. 排版、网格、色彩、媒体和动效语法；
6. 移动端、减少动效与低性能回退；
7. 主要风险、成本和验证方法；
8. 对 Design / Usability / Creativity / Content 的预期影响。

先独立发散三个方向，再给它们映射体验原型。任意两个方向必须在“故事结构、交互隐喻、签名机制”三项中至少有两项不同，不得只是换配色、文案或媒体。逐项检查它们与参考作品的构图、顺序、互动和资产相似性，并写出拒绝复制项。

推荐一个方向并解释取舍。没有真实审批时，可在自主任务中继续创建 `PROVISIONAL` 草案，但标记为“假定方向”；D-G1 仍为 `PENDING`，不得伪称利益相关者已批准。

### 5. 把方向变成设计系统

定义语义化系统，而不是先给固定数值：

- **内容与叙事**：信息优先级、故事节奏、证据与 CTA。
- **排版**：角色、层级、字宽、行长、语言覆盖与字体回退。
- **布局**：容器、列、间距、对齐、受控不对称和断点行为。
- **色彩**：语义角色、状态、对比目标和媒体叠加规则。
- **媒体**：图像/视频/3D 的叙事职责、比例、裁切和替代内容。
- **动效**：目的、时长范围、缓动家族、编排、并发上限与减少动效。
- **交互**：默认、悬停、焦点、按下、加载、空、错误、成功与禁用状态。
- **工程预算**：Core Web Vitals 目标、首屏依赖、媒体/字体/脚本预算和回退触发条件。

数值必须来自品牌、内容、设备测试或可追溯标准。团队默认值不算证据；无测量时只能标为 `PROVISIONAL`，同时写明来源类别、验证方法和替换条件。临时颜色、时长、断点或包体预算不得用于通过门禁。不要在无证据时输出看似精确的数值。

### 6. 先建立可靠基线，再渐进增强

先完成可读、可导航、可操作的语义化移动端基线，再加入动效、视频、Canvas、WebGL 或页面转场。

所有增强必须满足：

- 失败、禁用 JavaScript、低性能设备和减少动效时，核心内容与任务仍可用；
- hover 不是唯一入口；键盘、触摸与辅助技术有等价操作；
- 不接管用户滚轮、触摸或键盘滚动；
- 自动运动可停止；非必要交互动效尊重 `prefers-reduced-motion`；
- 视觉素材不承载唯一信息；
- 不虚构客户、指标、奖项、测试结果或品牌资产。

### 7. 双轨验证

**作品质量轨**：按官方四维权重预评 Design、Usability、Creativity、Content，并给每个分数附证据与置信度。

**发布质量轨**：检查关键任务、WCAG 2.2 AA、键盘/触摸、响应式、内容准确、错误恢复、浏览器回退及 Core Web Vitals。存在阻断项时，结论必须是 HOLD 或 NO-GO，即使作品质量分很高。

若 `$audit-awwwards-grade-uiux` 可用，调用它完成独立复审；否则按 `delivery-sop.md` 的门禁执行。

### 8. 自我迭代

每轮只处理一组共同根因：

1. 保存基线分数、指标、截图或任务结果；
2. 将差距映射到用户任务和评分维度；
3. 找到能同时改善多个问题的根因；
4. 提交最小可验证变更批次；
5. 重测变更项与回归项；
6. 记录前后差值、残余风险和下一决策。

进入 D-G5 前至少完成一次“基线 → 变更 → 同环境复测 → 关键路径回归”。零轮只能是 `HOLD`。达到已批准门槛后可以停止；若因成本、权限、内容或预算停止，必须保留真实决策者、时间、原文和版本记录。不要用 Agent 自己判断“收益低于成本”跳过首轮验证，也不要把固定轮数当作完成证据。

## 输出契约

以下核心项不得因“任务规模”省略；没有证据的项标为未知，不得补造：

1. 结论与推荐方向；
2. 事实、假设、未知和约束；
3. 参考矩阵与可迁移原则；
4. 三个概念领地及选择理由；
5. 页面故事与信息架构；
6. 设计系统与动效系统；
7. 响应式、无障碍、性能和回退规格；
8. 分阶段实施计划、负责人、依赖与验收标准；
9. 风险登记、审批状态与下一门禁；
10. 自评、证据置信度与下一轮实验。

每个实施任务写成：`问题/机会 → 变更 → 影响范围 → 验收证据 → 负责人/依赖`。

任何 `APPROVED` 或风险接受记录必须包含真实批准主体、批准原文、时间、产物版本和适用范围。缺任一项即为 `PENDING`。不得由产物作者批准自己的发布。

## 红线

- 把 Awwwards 当作固定深色炫技风格；
- 先堆技术效果，再寻找理由；
- 用奖项审美压过产品任务、内容真实性或用户控制；
- 只设计桌面截图，不定义真实状态与移动行为；
- 通过删焦点、低对比度、滚动劫持或不可暂停视频换取“高级感”；
- 引用过时规则却不标版本，或把内部预测冒充官方评审；
- 在没有测试证据时宣布“已达到 Awwwards 水准”或“已批准上线”。
- 跳过任一门禁却宣布 GO，或在零轮复测后进入 D-G5；
- 通过临时默认值、作者自批或口头催促伪造通过证据。
